# 盲测协议 v1 — 化身保真度(Phase 0 门槛:通过率 ≥ 60%)

> 这是内测/研发用的研究流程,不是产品功能。目的只有一个:用可重复的方法回答
> 「化身像不像本人」,并把失败归因到能改的地方(蒸馏、prompt、LoRA)。
> 评测期间固定模型、卡片快照和 prompt 版本,否则分数不可比。

## 1. 参与者与前置条件

- 每位参与者至少 8 篇日记、化身「在用」的理解 ≥ 10 条(我 → 人格卡片 里看)。
- 评测前把参与者**最近 2 篇日记**设为「不用于化身」(长按 → 不再用于化身),作为未参与训练的留出材料;评完再打开。
- 参与者本人、一位熟人(可选)、一位评审员各一份记录表。

## 2. 题库(每人 8~12 题,从下面各组抽)

出题原则:问「会怎么说、怎么选」,不问「日记里写过什么」;不让模型复述日记。

**价值排序**
1. 工作和生活冲突时,我通常怎么取舍?
2. 朋友做了一件我不认同的事,我会说什么?
3. 一笔意外的钱,我最可能怎么用?

**口头表达**
4. 朋友问「最近怎么样」,我会怎么回?
5. 别人夸我,我一般怎么接?
6. 我拒绝一个不想去的饭局,会怎么说?

**日常偏好**
7. 周末完全自由的一天,我会怎么过?
8. 我最受不了什么样的环境或场合?
9. 我放松的时候会做什么?

**轻压力情境**
10. 工作/学业上搞砸了一件事,当晚我会怎么想?
11. 有人在群里误解了我,我会怎么处理?
12. 很久没联系的人突然找我,我第一反应是什么?

## 3. 流程

1. 对每道题,化身在自聊里作答(用「问一个能验证我的问题」入口或直接输入),记录原文。
2. 参与者本人**不看化身回答**先写自己的真实回答(或由熟人写一版「我觉得 TA 会这么说」作为人工基线)。
3. 评审员把「化身回答 / 真实回答 / 人工基线」打乱顺序,交给参与者判断每条是「像我 / 不像我 / 不确定」,并写一句原因。
4. 通过率 = 化身回答被判「像我」的比例;「不确定」不算通过。

## 4. 失败归因(每条「不像我」必须归入一类)

| 类别 | 现象 | 下一步改哪里 |
|---|---|---|
| 文体不像 | 句长、语气词、标点、收尾方式不对 | 说话范例构造(对话对)、LoRA |
| 观点不对 | 立场、偏好与本人相反或无依据 | 卡片抽取 prompt、卡片排除/确认 |
| 把暂时当人格 | 把一时情绪当成长期性格 | kind=mood 的注入方式、卡片时效 |
| AI 讨好/空泛 | 过度热情、总结升华、列清单 | 自聊 prompt 约束、DPO 偏好对(Phase 1) |

## 5. 记录与版本

每轮记录:日期、参与者数、题数、通过率、四类失败各占比、模型与 prompt 版本(git 提交号)、卡片快照时间。
通过率上不去时先看失败分布,再决定改蒸馏还是上 LoRA;过了 60% 再推进上架相关事项(HANDOFF.md「上架还差几步」)。
